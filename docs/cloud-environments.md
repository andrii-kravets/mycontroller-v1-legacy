# Хмарні середовища Claude Code (claude.ai/code)

Джерела (перевірено 2026-10-23):
- https://code.claude.com/docs/en/claude-code-on-the-web
- https://code.claude.com/docs/en/cloud-environments

Документація змінюється швидко, тому перед важливими налаштуваннями звіряйтеся з офіційними сторінками.

## 1. Що це

Кожна хмарна сесія працює в окремій віртуальній машині (VM). Середовище (environment) — це збережена конфігурація цієї VM:

| Поле | Призначення |
|---|---|
| Доступ до мережі | Які зовнішні домени доступні з VM |
| Мережеві секрети | API-ключі, які проксі підставляє в запити; ключ у VM не потрапляє |
| Скрипт налаштування | Bash-скрипт, що виконується до старту Claude; результат кешується |
| Змінні середовища | Формат `KEY=value`; видимі будь-якій команді в сесії |

Середовище не впливає на модель і не визначає репозиторій чи гілку — вони обираються окремо.

## 2. Рівні доступу до мережі

| Рівень | Що дозволено |
|---|---|
| None | Нічого, окрім Anthropic API |
| Trusted (типовий для Default) | Реєстри пакетів (npm, PyPI, crates.io), GitHub, Docker Hub, хмарні SDK |
| Full | Будь-який домен |
| Custom | Власний список доменів, за бажанням разом із типовими |

Рекомендація: Trusted для більшості задач; Custom, коли потрібні конкретні домени; Full лише у виняткових випадках (найбільший ризик витоку даних).

Зміна рівня діє на вже запущені сесії приблизно за хвилину.

## 3. Коли створювати окреме середовище

Створюйте, коли проєкти різняться за:
- залежностями (різний скрипт налаштування);
- мережевими потребами (різні домени);
- секретами та змінними (ізоляція ключів між проєктами);
- рівнем довіри до коду.

Лишайте Default, коли потреби однакові й прості. Дрібні різниці (наприклад, `LOG_LEVEL`) задавайте прямо в команді, а не окремим середовищем.

Практичні правила:
1. Називайте середовище за проєктом (наприклад, `mycontroller-esp`).
2. Принцип мінімуму: лише потрібні домени й ключі.
3. Окремий ключ на проєкт, за можливості з правами лише на читання.
4. Прості залежності краще описати в репозиторії (`.claude/`, SessionStart-хук), бо вони їдуть разом із кодом. Скрипт налаштування — для важких установок, які мають кешуватися.
5. Кількість середовищ не збільшує витрат: ліміт підписки спільний і залежить від обсягу роботи.

## 4. Секрети та змінні

- API-ключі додавайте в Мережеві секрети, а не в змінні середовища: змінні бачить будь-хто, хто користується середовищем, і будь-яка команда в сесії.
- Мережеві секрети доступні на планах Pro, Max, Team, Enterprise.
- Не вставляйте токени й паролі в чат.
- Зміни змінних діють на вже запущену сесію лише після відновлення її VM; для негайного ефекту задайте значення в команді або почніть нову сесію.

## 5. Скрипт налаштування

- Виконується до старту Claude; пропускається, якщо є кешоване середовище.
- Скрипт довше за ~5 хвилин не кешується.
- Для встановлення потрібна мережа (при None інсталяції не працюють).
- Скрипт не бачить збережених змінних і секретів середовища.

Шаблон для ESP/PlatformIO-проєкту (перевірте під свої потреби):

```bash
#!/bin/bash
set -e
pip install --quiet platformio
```

Для цього потрібні домени PyPI (є в Trusted) і, ймовірно, `registry.platformio.org` та пов'язані (додайте через Custom).

## 6. Переваги та недоліки

Переваги:
- сесія працює, коли ноутбук закрито; керування з телефона чи браузера;
- ізоляція від вашої машини;
- паралельні задачі;
- auto-fix для PR (CI та коментарі);
- нічого не треба встановлювати локально.

Недоліки:
- репозиторії й PR лише GitHub (для інших хостингів — лише локальний bundle без push назад);
- VM призупиняється після кількох хвилин простою й може бути звільнена; фонові процеси не відновлюються;
- немає доступу до локальної мережі та пристроїв (ESP, локальний MQTT-брокер);
- частина команд терміналу недоступна (`/plugin`, `/resume`);
- недоступно для організацій із Zero Data Retention чи HIPAA.

## 7. Вартість

- Окремої плати за VM немає: хмарні сесії входять у план (Pro, Max, Team, Enterprise).
- Витрати йдуть у ліміт підписки разом з рештою використання Claude і Claude Code; паралельні задачі витрачають ліміт пропорційно швидше.
- Додаткове використання понад ліміт — pay-as-you-go за тарифами API, вмикається явно.
- Точні ліміти для хмарних сесій у документації не наведено; дивіться Settings → Usage у своєму акаунті та https://claude.com/pricing.

## 8. Безпека

Захищено:
- VM ізольована від вашої машини й від інших сесій;
- облікові дані GitHub лишаються на серверах Anthropic, git-операції йдуть через проксі;
- мережеві секрети підставляються проксі поза VM.

Ризики:
- Full дозволяє звертатися до будь-якого домену (витік даних, prompt injection);
- навіть при None трафік до Anthropic API лишається, тому теоретичний витік можливий;
- змінні середовища видимі всім, хто користується середовищем;
- публічне шерінг сесії (Pro/Max) може відкрити код і облікові дані з приватних репозиторіїв;
- відповіді Claude в PR публікуються від імені вашого GitHub-акаунта (з позначкою Claude Code) і можуть запустити автоматизацію на `issue_comment`.

## 9. Як створити середовище

1. claude.ai/code → екран нової сесії → перший елемент у рядку під полем вводу (селектор середовища).
2. «Нове середовище» (New environment) → заповніть ім'я, рівень мережі, змінні, скрипт.
3. «Додати середовище». Нова сесія одразу використає його.
4. Редагування: значок налаштувань біля середовища у списку або «Edit cloud environment» через стрілку біля назви запущеної сесії.

Особисті середовища видно лише вам; для команд Owner може створювати спільні.

## 10. Контрольний список

- [ ] Рівень мережі мінімально потрібний (початок: Trusted)
- [ ] Ключі лише в Мережевих секретах, окремі на проєкт
- [ ] Назва середовища відповідає проєкту
- [ ] Скрипт налаштування вкладається в ~5 хв
- [ ] Сесії з чутливими даними не шеряться публічно
